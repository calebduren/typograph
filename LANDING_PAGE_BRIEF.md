# Typograph landing page

**Implemented 17 September 2026:** the home page now uses the hardened chat plugin and the comparison below. See [LANDING_TEST.md](LANDING_TEST.md) for verification and remaining evaluation work.

Implemented direction following the hardening pass. English-only scope and the reference sites are user decisions. Mode: Persuade. Target: `/`, implemented by `apps/playground/src/main.tsx`, `ChatComparison.tsx`, and `landing.css`.

## Job

Help a developer building an AI chat interface see a worthwhile improvement, understand its boundaries, and adopt the small Remark plugin. The visitor should be able to replay a real transformation before reading an API explanation.

The homepage centers the tested chat package.

## Interaction and implementation

The homepage uses `@calebduren/typograph` through the tested Streamdown renderer. Keep the real transport/reconnect fixture separate from the public comparison: recorded text streams locally through the same plugin. This keeps the landing page easy to host as static assets. The comparison renderer loads in a separate bundle after the page shell; the comparison heading, viewport, and fragment target remain mounted to preserve layout and navigation.

Desktop uses equal reading widths for a fair side-by-side comparison, with a shared maximum of 48ch initially and a 28–64ch measure control. The ch unit follows the font’s zero glyph, not a literal character count, and each pane clamps to its available width. At 800px and below, an Original/With Typograph switch selects one pane in the same reading area, retaining playback position and width. The framed page caps at 78rem; gutters reduce at 1100px and 800px, and the hero stacks at 520px. These composition choices belong to this route within Typograph's established identity.

The default is a completed text example with smart punctuation, non-breaking spaces, hanging punctuation, and highlights all on. All visitors start in this static state. Manual replay can pause, scrub, and continue. One substantial studio-review example is shared by Text and Conversation. There is no example picker. An inline original editor capped at 12,000 characters and a Reset example action support trying other text. The comparison workspace, from refinement controls through caption, fills 100dvh. A 48rem minimum keeps the desktop reading area useful. At 800px and below, the workspace uses natural height with a shared reading viewport of clamp(24rem, 60svh, 36rem), 16px base text, stacked switches, and 44px touch targets. Only desktop refinement controls stick to the top; mobile controls remain in page flow. The heading stays above it; no forced scroll snapping is used. Both columns are children of one native scroll container; no JavaScript synchronizes their scroll positions. The editor grows to its full source height using a CSS sizing mirror and has no separate vertical scrollbar. Mobile Original/With Typograph switches reuse the same scroll container. Replay follows new text until the visitor scrolls back. Mobile comparison uses complete versions rather than a split reveal, since typography can change line wrapping. Both vertical scrollers—the shared comparison and agent prompt—have soft 96px edge fades with eased opacity stops that disappear at their respective endpoints and when the content fits. They update with scrolling, streaming, edits, recipe switches, and resizing. The Markdown editor always contains the full source, while both rendered panes share the same streaming prefix; editing cancels replay and immediately formats the complete new input. In Conversation mode, matching user bubbles, scripted thinking stages, and streamed answers appear in both rendered columns. All view selectors share the same button-style segmented control. Show changes only toggles annotation paint and absolute rulers; annotation markup is stable and the legend reserves its space, preserving text geometry and viewport height. The caption explicitly says “Scripted conversation · No model call.” Streaming prose is outside live announcement regions. Controls have keyboard access and visible focus, and code/table overflow stays local. Reduced motion removes smooth scrolling and switch transitions.

External and resource links open in a new tab; page-section links remain in the current tab. The example guide links to the real integration guide, and illustrative addresses are literal code rather than clickable destinations. All navigation links remain visible on phones.

Raw Markdown remains the canonical source. There are no comparison copy buttons; native selection copying is sufficient for the preview. Product integration docs still explain original-text copying from stored SDK messages. Installation success feedback lives in its copy button, with an inline alert only for copy failure. Pasted text stays in the browser, remote images render as descriptions without a request, and the comparison never calls a model. There is no language picker: English is the product's deliberate scope. The docs retain the response-language requirement and describe safe opt-out for other or mixed-language content.

Hanging punctuation is a separate optional Rehype helper and stylesheet, scoped to opening quotes at the start of English, left-aligned paragraphs and headings outside lists. Bulleted and numbered lists, including their nested paragraphs and headings, keep quotes inline. It uses real text and ordinary inline layout/transforms, without native hanging-punctuation support or DOM measurements. It does not hang every wrapped line ending.

Recommend CSS `text-wrap: pretty` for completed prose and ordinary wrapping during streaming. Final-word nonbreaking spaces remain an explicit advanced opt-in; the demo does not force a final-word join.

Do not display an npm install command for the candidate until the package name and published artifact are verified. Pre-release visitors can use the source and integration guide.
